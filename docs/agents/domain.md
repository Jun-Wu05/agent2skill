# Domain 文档

工程技能在探索代码库时应如何消费本仓库的领域文档。

## 布局：single-context

本仓库是 **single-context**：整个仓库共用一份根目录的 `CONTEXT.md`，架构决定放在 `docs/adr/`。没有 `CONTEXT-MAP.md`，也没有各子项目自己的 `CONTEXT.md`；在第一次真正写下词条之前，不要创建它们。

## 探索之前先读这些

- 仓库根目录的 **`CONTEXT.md`**（共享的领域术语表）。
- **`docs/adr/`**：读与你即将工作的区域相关的 ADR。

如果这些文件不存在，**静默继续**。不要指出它们缺失，也不要一开始就建议创建。`/domain-modeling` 技能（经由 `/grill-with-docs` 和 `/improve-codebase-architecture` 到达）会在术语或决定真正被敲定时才惰性创建它们。

## 使用术语表的词汇

当你的输出提到一个领域概念（issue 标题、重构提案、假设、测试名），使用 `CONTEXT.md` 里定义的术语。不要漂移到术语表明确回避的同义词。

如果你需要的概念还不在术语表里，这是一个信号：要么你在发明项目不用的语言（重新考虑），要么存在真实缺口（记下来给 `/domain-modeling`）。

## 标记 ADR 冲突

如果你的输出与某个已有 ADR 矛盾，明确指出而不是静默覆盖：

> _与 ADR-0007（事件溯源订单）矛盾，但值得重新讨论，因为…_
